## Target

- [ ] T1: 基于当前实现判断产品是 Markdown 编辑器、阅读器还是兼具两者，并说明依据。
- [ ] T2: 评估现有名称与实际定位的匹配程度，提出合适的候选名称与推荐理由；不执行重命名。

## Scope

- 只读分析当前源码并提出命名建议；不修改产品、配置、仓库名称或发布身份。

## Decisions

- 当前实现是以 Markdown 为核心的本地多格式文档阅读器，不是编辑器。`src/platform.ts` 只暴露文件读取接口；`src-tauri/src/main.rs` 注册的命令不包含正文写回；`README.md` 明确排除编辑。`writeLibrary` 保存的是收藏与最近记录，不是文档正文。
- `tasks/tasks/edit-article-content.md` 记录了编辑和保存目标，但没有实现证据，不能当作当前功能。
- Markdown 渲染支持代码高亮、脚注、任务列表显示、公式及 Mermaid；另支持 JSON、HTML、PDF，产品定位不宜被 Editor 限定。
- 建议首选 Folio：以文档为中心、不限定只读或编辑；如更强调 Markdown，可考虑 Markleaf；如保留现有品牌，可简化为 LinguaMark。Pagewise 为另一中性候选。
- Reader 符合当前功能；Lingua 容易让人联想到语言或翻译，当前产品功能并不以此为中心。更名的主要理由应是品牌定位，而非已有编辑能力。
- 候选仅为命名建议，未核验商标、域名或应用商店同名情况；最终名称尚未由用户选择。

## Plan

1. 向用户说明当前产品定位与编辑能力缺失的源码依据。
2. 比较候选名称，给出首选与保留原品牌的低变更方案。
3. 用户若选择名称并明确要求实施，另行对齐实际重命名范围；先核验名称可用性及应用身份、数据存储、更新链路兼容边界。

## Verification Boundary

- 本次依据当前工作区静态源码和文档，不代表已安装应用的实际运行版本。
- 未修改产品文件，未运行构建或测试；命名建议不构成商标或域名可用性保证。
