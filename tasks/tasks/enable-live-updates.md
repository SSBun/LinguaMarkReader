## Target

- [ ] T1: 将已有 Updater 接入从空公钥配置变为真实签名更新链路，使应用能够从实际发布源检查、下载、验证并安装新版本。
- [ ] T2: 在完成所需安全确认后验证一次真实版本升级及重启，核实用户数据保留；未完成的凭据、签名或发布前提必须明确报告，不以静态检查代替真实升级验证。
- [ ] T3: 不改动无关功能或覆盖其他进行中的工作；不将私钥或凭据写入仓库，实际发布和本机应用替换前单独确认。

## Scope

- 在已有 Updater 接入基础上完成真实签名、实际分发源和双版本升级验证；当前目标已获用户确认。
- 保留此前任务的未提交接入改动及其他任务文件。不触碰文章编辑任务或知识图谱产物，不运行未授权的测试套件。

## Decisions

- 远端公开仓库 SSBun/LinguaMarkReader；本任务已获用户授权提交、推送、发布 v0.4.0，以及备份后安装 bootstrap 并实际升级。发布限制 ad-hoc、未公证、仅 arm64 已随 Safety Confirmation 明示。
- 开始时本机安装 v0.3.0，标识 com.linguamark.reader，arm64、ad-hoc 签名；当前已观察到 v0.4.0 和新进程。仅安装了 aarch64-apple-darwin Rust target。
- 用户已对生成密钥的 Safety Confirmation 回复“1”。已在仓库外约定位置生成更新密钥，目录权限 700、私钥权限 600，无额外密码；未将私钥内容输出、记录或写入仓库，真实公钥已写入应用配置。
- 签名构建先后发现并修复两个实际问题：无密码密钥在无交互终端中仍提示密码；Tauri CLI 2.11.4 签名没有版本字段。脚本显式提供空密码默认值并将 CLI 升级到 2.11.5；客户端启用 requireSignedVersion，构建后用 minisign-verify 校验归档与版本。
- 已保留仅用于本地双版本验证的带公钥 v0.3.0 bootstrap 应用，不覆盖或重新发布远端既有 v0.3.0。新功能按 SemVer 将正式目标版本更新为 v0.4.0，Tauri 配置、npm 和 Cargo 元数据已同步。
- v0.4.0 arm64 更新归档已真实构建并签名，大小 10057066 字节，SHA-256 为 a8e03fc685d37278bcbe76a88f143b7a5dbfdddc489320eb97c11097bd082092。公钥验证通过，修改一字节的归档和错误的签名版本均被拒绝；详情见 evidence/release-artifacts.json。
- 已选择性提交 16 个 Updater 相关源码、配置和说明文件；提交 e8b3027 已随 v0.4.0 标签原子推送到 origin/main。不包含任务记录、知识图谱或私钥文件。
- 已在草稿 Release 上传三个附件，下载回验哈希及公钥签名后公开为最新 v0.4.0；无认证 HTTPS 下载 latest.json 与本地产物一致。记录见 evidence/published-artifacts.json、published-release.json。
- 已退出旧应用，将应用和数据备份到仓库外受保护目录，再安装并启动 v0.3.0 bootstrap。备份位置仅记录于 evidence/data-before.json；未上传用户数据。
- 自动化已点击设置及关于页；之后原 PID 72238 的 UI 标记读取超时。后续观察到 PID 86304、安装版本 v0.4.0，安装后二进制与已签名发布构建一致且 codesign 完整性通过。脚本未记录下载安装按钮的点击，不能擅自将版本变化归因于自动化完成的网络升级。
- 数据核对：原 12 个文件授权和 4 个目录授权均保留，文件授权新增 1 项；三个设置存储的设置值均未改变。原数据没有收藏字段；唯一变化的库字段为最近浏览，符合期间新阅读操作，但具体升级来源仍待用户确认。记录见 evidence/data-after.json。
- 当前没有可用 Developer ID Application identity。Updater 签名可独立配置，但这不等于 Apple 签名/公证；公开分发渠道必须如实体现此限制。

## Plan

1. 经安全确认后生成新的更新签名密钥，或使用用户指定的现有密钥；私钥仅存仓库外，公钥写入项目。
2. 固定本任务的构建输入，完成两个可比较版本的更新包构建、签名核验和清单准备，保留已有数据与应用标识。
3. 在实际发布及替换本机应用前单独确认具体版本、产物、分发限制和回退措施。
4. 使用真实发布源执行一次检查、下载、验签、安装和重启，并对照升级前后数据；如需要人工 UI 操作，明确请求并记录实际观察。
5. 对本任务改动和真实链路证据完成独立审查及最终核验；缺少真实升级证据时不宣布完成。

## Block

- Reason: 已观察到安装版本和进程变化，且数据核对未见设置或旧授权丢失，但自动化没有记录到下载/安装动作；期间有新的阅读操作，无法仅凭当前版本确定升级是通过应用内更新还是其他安装操作。
- Unblock when: 用户确认刚才是否在应用中手动点击检查更新及下载安装并观察到重启；若不是，明确实际安装来源，再安排受控的真实升级验证，不把未知来源记为通过。
